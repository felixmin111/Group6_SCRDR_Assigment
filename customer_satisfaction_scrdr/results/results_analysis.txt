3. MISCLASSIFICATION ANALYSIS (7 errors)
--------------------------------------------------------------------------------

ERROR TYPE A: Neutral misclassified as Satisfied (4 cases)
  Root cause: R6 [repeat_customer=yes, issue_resolved=yes, tone=neutral] fires
  and produces "Satisfied". However, these records have additional negative
  signals (e.g., poor support, slow response, low product quality) that R6
  does not check. R6.1 partially addresses the slow+low case, but not all
  combinations.
  Fix applied: Added exception R6.2 under R6 for cases where
  support_experience=poor, which more specifically captures this boundary.

ERROR TYPE B: Neutral misclassified as Dissatisfied (2 cases)
  Root cause: R5 [product_quality=low, tone=negative] and R2
  [tone=negative, issue_resolved=no] are too aggressive — they classify as
  Dissatisfied even for boundary Neutral cases where the issue was partially
  mitigated (e.g., support was average, product quality was low but tolerable).
  Fix applied: Added exception R5.1 and R2.2 for cases where
  support_experience=average and repeat_customer=yes (mitigating context).

ERROR TYPE C: Dissatisfied misclassified as Neutral (1 case)
  Root cause: The record (slow/low/good/no/neutral/no) does not trigger any
  specific Dissatisfied rule. Tone is "neutral" and support is "good", so R2,
  R4, R5 do not fire. R0 (default = Neutral) wins.
  Fix applied: Added R7 [response_time=slow, product_quality=low,
  issue_resolved=no] → Dissatisfied as a direct exception of R0.

--------------------------------------------------------------------------------
7. OBSERVATIONS AND CONCLUSIONS
--------------------------------------------------------------------------------

  1. SCRDR correctly classifies all Satisfied samples (recall=1.0). The
     rule set strongly encodes positive satisfaction signals.

  2. The Neutral class is structurally difficult — it represents the boundary
     between satisfaction and dissatisfaction. SCRDR handles it by relying on
     the default rule (R0) as the catch-all, which means patterns that do not
     clearly align with either extreme fall through to Neutral correctly.

  3. Incremental learning is clean and additive. Each correction adds exactly
     one new rule and does not affect any previously correct classifications.
     This is the core SCRDR guarantee: monotonic improvement.

  4. The rule tree provides full traceability for every decision, which is
     essential in customer service contexts where explaining a classification
     to a domain expert is a requirement.

  5. The system is ready for expert review: any rule can be inspected,
     discussed, and refined by adding more specific exceptions without
     disrupting existing behaviour.
